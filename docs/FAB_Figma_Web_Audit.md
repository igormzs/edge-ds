## 3. Completeness: two flagged gaps, not silently fixed

**Gap 1, Code Connect drift (`src/components/Fab.figma.tsx`).** The mapping's `Variant` enum key `Circular` does not match the live component set's real property option, which is named `Round`. Its `Color` enum lists `Error`, `Success`, `Info`, and `Warning`, none of which have a live Figma variant to bind to (see Gap 2). Fixing the Code Connect file itself was out of scope this pass (only the Figma canvas, its tokens, and `brandTheme.ts` were asked for); flagging the exact mismatch here so a future pass can correct the mapping once the missing color variants (or a renamed `Variant` option) are decided.

**Gap 2, missing `Error`/`Success`/`Info`/`Warning` Figma variants.** MUI's real `Fab` code genuinely supports these four colors today, verified directly against `Fab.js`'s generic palette-loop mechanism, the same one Button uses. Figma's live `<Fab>` set simply has never had these variants built. **Logged as a product gap for design to pick up as its own dedicated pass** (build the four color variants against the same grid, then re-run this token migration against the richer set), the same pattern already used for Drawer's missing anchor/variant axis and Backdrop's own earlier Style x Visibility gap.

Both gaps are structural (a missing variant, a mismatched enum key), not token-hygiene issues, and neither was silently patched over.

## 4. What was migrated

- Ran a full Gap Analysis across the entire 120-variant grid (`Form` x `Size` x `Color` x `State`), not a single-instance spot check, per instruction.
- Checked `Components/Button/*` first, as instructed, before proposing any new token. Found that `Primary`, `Secondary` (mapping to Button's already-migrated `Neutral` slot), `Inherit`/`Default`'s shared grey surface, and the shared `Disabled` pair were **all already covered by pre-existing Button tokens**, verified each one's existence and EDGE-palette-collection membership by variable ID before sign-off (`Components/Button/Neutral/BG/Default` `VariableID:888:30`, `Neutral/BG/Hover` `VariableID:888:31`, `Inherit/BG/Default` `VariableID:902:6`, `Inherit/BG/Hover` `VariableID:902:7`, `Switch/Knob/FocusRing` `VariableID:920:8`).
- Rebound all 360 fill roles across the 120-variant grid in one pass (120 backgrounds, 60 text nodes, 120 icon vectors, 30 white focus rings, 30 inner focus-ripple accents), grouped by real per-variant Color/State identity, not by whatever the raw binding happened to already say (name-driven rebinding).
- Created exactly one new token, `Components/Fab/Shared/FocusRing` (aliasing `Semantic/Surface/Paper`), after confirming it did not already exist and matching the established `Components/Switch/Knob/FocusRing` sibling precedent.
- Normalized one inconsistency found during rebinding: `Default`'s focus-ripple inner accent was bound to a generic MUI `text/focusVisible` raw value instead of matching its own text token the way the other four colors already did; rebound to `Semantic/Text/Primary` at the same local 30% opacity to make the pattern consistent, flagged rather than silently left as a one-off.
- 3 consecutive clean residual scans (0 raw/unbound fills or strokes) across the entire component set after rebinding.
- Verified via direct inspection of `node_modules/@mui/material/Fab/Fab.js` (not assumed) that MUI's own generic palette-loop mechanism already produces every rebound color/state combination on the web side with zero additional style overrides, the one exception being the new focus ring.
