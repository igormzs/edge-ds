## 3. Completeness: two flagged items, neither blocking

**Thin web coverage.** `breadcrumbs/page.tsx` is the *only* real `@mui/material` `Link` usage site anywhere in the codebase. It renders `<Link underline="hover" color="inherit" href="/">`, a pure downstream consumer — nothing in that file needed touching, it inherits the new `MuiLink` `brandTheme.ts` entry automatically. Flagged because there is very little existing web surface to validate parity against, not because anything is broken.

**Standalone-demo instance override.** See §2's last row: one real-world Gallery instance carries its own raw `text/secondary` override, discovered only because the Documentation screenshot showed a visibly different shade than expected. Left untouched, flagged for a future pass, not silently absorbed into this migration's scope.

## 4. What was found (discovery, before and during the build)

- A real 18-variant `COMPONENT_SET`, but only 14 of 18 existed at Step 1: `State=Focused` was only built for `Underline=None` (both colors), missing for `Underline=Always*` and `Underline=On Hover`.
- Bespoke (not `<Typography>`-composed) text, confirmed by value match to `Body/Medium`'s spec, not by name.
- Two raw MUI-palette bindings across the whole set (`primary/main`, `text/primary`), each used identically across all three `State` values, no per-state color variation, confirmed by a full binding scan of all 18 variants before proposing any token.
- **A real structural gap caught by screenshot, not assumed away:** after cloning the 4 missing `Focused` variants from their `Hovered` siblings (per the confirmed build plan), a verification screenshot showed the 2 pre-existing `Focused` variants had a 2px focus-ring outline the 4 new clones lacked. Direct node comparison confirmed the root `COMPONENT`'s own `strokes` property, a raw unbound `rgba(0, 0.373, 0.8, 1)`, `strokeWeight: 2`, present only on `Focused` variants and invisible to a fills-only inspection. Added to all 4 new variants to match, verified by a second screenshot before moving on.
- The legacy `_Library / Component Heading` + `Grid` wrapper was present, with the real `<Link>` set nested inside it, same as every prior component.
- What Step 1 called a "breadcrumbs" real-world mockup was actually a standalone `<Link>` demo instance sitting in the shared library header template's own internal `Box`, not a breadcrumb-nav-specific usage — the label "breadcrumbs" in the earlier discovery report was imprecise; corrected here.
