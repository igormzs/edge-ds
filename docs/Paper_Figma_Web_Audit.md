## 3. Completeness: two explicit open calls

**1. The `Semantic/Elevation/*` tier is newly established, not a routine alias.** Every other Semantic-tier token migrated in this project so far aliased an existing precedent (`Semantic/Surface/Paper`, `Semantic/Border/Default`, etc.). This is the first component to require a wholly new namespace, and its 24 values happen to equal MUI's stock shadow scale exactly rather than encoding an EDGE deviation (see §2). Flagged for explicit awareness going forward: any future component needing shadows (Card's own eventual pass, potentially Menu/Popover/Snackbar) should reuse this tier rather than re-deriving a parallel one.

**2. The two pre-existing real-world mockups predate the Two-Frame Canvas standard.** Rather than leaving them as separate stray top-level frames, or silently dropping them, this pass folded both into the new Gallery as their own `REAL-WORLD USE CASE` sections (`REAL-WORLD USE CASE — NAV BAR (UNDETACHED)` and `REAL-WORLD USE CASE — TOPBAR + CARD (DETACHED)`), matching the same handling already established for Drawer's four mockups and Link's two. Explicitly flagged as a decision made, not a silent default — see the build report for sign-off.

## 8. 2026-08-07 correction pass: residual MUI-palette bindings + both Top Headers rebuilt

**Root cause, stated plainly, not softened.** The original Step 5 pre-commit sweep (§6) *did* find all 24 remaining raw MUI-palette-bound nodes — same node IDs, same variable names, nothing was missed by the walk itself. The mistake was scoping: those 24 sat inside the two pre-existing real-world mockups' own content, and I classified them as "pre-existing mockup content, out of scope," mirroring Dialog's own precedent for cross-component composition debt. That precedent doesn't actually apply here — these are live, still-resolvable `MUI palette` library bindings sitting on Paper's own dedicated page, exactly the kind of thing a "final sweep before commit" is supposed to catch, and Figma's own color-picker panel surfaced them immediately. Caught via direct visual inspection (Figma's Selection/Libraries panel, not a script), not by the automated walk.

**What was rebound (10 of 24):**

| Raw binding | Target | Basis |
| :--- | :--- | :--- |
| `background/default` (2 mockup-root frames), `background/paper-elevation-1` (1 `Topbar`) | `Semantic/Surface/Paper` | Exact value match (`#ffffff`) |
| `common/white/main` (1 `Title` text) | `Brand/White` | Exact value match |
| `text/primary` on 2 `TEXT` nodes | `Semantic/Text/Primary` | Disclosed near-match (`#000000de` vs. solid `#212121`), same accepted class as Link's own `text/primary` rebind |
| `text/primary` on 2 `VECTOR` icon nodes | `Semantic/Icon/Default` | Disclosed near-match, correct role-specific token per Icons' own precedent (icon glyph, not text) |
| `text/secondary` on 2 `TEXT` nodes | `Semantic/Text/Secondary` (`#616161`) | Near-match to raw `rgba(0,0,0,0.6)` ≈ `#666666`, confirmed this token already exists from List's own migration, not invented |

**What was deliberately left (14 of 24), and why:**
- **7 unbound literal `#ffffff` fills** (`Left Side`, `min-height`, `Container`, `Content`, `Spacing | Vertical` ×3) were out of the original Issue-1 scope (they're unbound literals, not MUI-palette *bindings*) — closed in a follow-up pass the same day: checked each node's real parent context (all sit inside `<Toolbar>`/`<Paper>` or `<Card>`/`<CardContent>` compositions), confirmed all seven are genuinely background/surface-role fills, and bound all seven to `Semantic/Surface/Paper`.
- **7 `action/hover` bindings on `<Skeleton>` instances** remain, deliberately not forced. Checked `Semantic/State/Hover` first — it resolves to a solid turquoise tint (`#bce8e9`), nothing like the translucent 4%-black shimmer `action/hover` actually renders; forcing it would be a real visual regression, not a fix. No other existing token fits a translucent hover-overlay role. This is `<Skeleton>`'s own future migration debt, not Paper's.

**Both Top Headers rebuilt from a direct diff against `Link`'s verified, closed reference** (not re-derived from the written §1.2 spec, which turned out to be stale on one point — see below):
- **Component Gallery header** had no Logomark and no Wordmark Stack at all — it used a single ad hoc merged text run (`"EDGE-DS · Component Gallery · Paper"`) that doesn't exist anywhere in the real pattern. Rebuilt from scratch to match the reference's actual Logomark + two-line "EDGE-DS"/"Documentation" stack (the Gallery/Documentation distinction lives in the eyebrow text below, never in the top chrome bar).
- **Documentation header**: the Logomark was a flat teal rounded rectangle; the real reference uses an **image-fill** logo asset — cloned the real node directly from `Link` rather than approximating it. The wordmark text used a literal `#079C9C`, which doesn't match the shipped reference's `Brand/Primary/500`-bound `#009F9B` — the written spec's literal value is stale relative to what's actually built and live, flagged per §9 of the Figma structure doc rather than silently propagated. `itemSpacing`/`counterAxisAlignItems`/inner-stack spacing were also off (`0`/unset/`2` vs. the reference's `12`/`CENTER`/`0`).
- **Both headers** had a literal `#262D33` background; the real reference binds this to an existing token, `Documentation/Header/BG` — both now bound. Frame names corrected from hyphen (`Top Header - EDGE-DS`) to the reference's em dash (`Top Header — EDGE-DS`).

**Cross-component discovery (no other pages touched):** checked all 15 other completed component pages for the same two bugs. Background binding is universally correct everywhere else (100% already on `Documentation/Header/BG` — Paper was the only outlier). Header naming (hyphen vs. em dash), however, is a genuine, pre-existing, widespread inconsistency across the file, unrelated to this pass — see the newly-logged item in `EDGE-DS_Claude_Account_Handoff.md` §4.

**Final verification:** 3 consecutive clean residual passes (403 nodes each) confirm 0 unbound literal fills and 0 unexpected raw variable bindings remain anywhere on the page, other than the 7 disclosed, deliberately-un-forced `action/hover` residuals above.
