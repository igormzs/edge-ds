# Rating Component 1:1 Figma-to-Web Parity Audit

Built 2026-08-11. Multi-master family, but a structurally novel shape compared to every prior pass: `<Star>` (a self-contained icon component) and `<Rating>` (a composition of 5 `<Star>` instances), plus a real cross-page dependency on shared icon masters hosted on the Icons page.

## 1. Master component structure

- `<Star>` — real `COMPONENT_SET`, node `6562:39569`, page "     Rating" `6562:39536`. **15 of 18 possible variants** built: `Size` (Large/Medium default/Small) x `Active` (False/Half/Full) x `Hovered` (false default/true). The missing 3 are all `Active=False, Hovered=true` (an empty star's own hover appearance), across all 3 sizes — a real, confirmed gap, not fabricated.
- `<Rating>` — real `COMPONENT_SET`, node `6562:39624`, 6 variants: `Size` (Large/Medium default/Small) x `Disabled` (False default/True). **No `readOnly` or `precision` variant axis exists** — confirmed via `mainComponent.parent.id` resolution that every one of its 6 variants composes a fixed 5 real `<Star>` instances (Full, Full, Half, Empty, Empty — an illustrative "2.5 star" default), not a switchable value.
- The half-filled state is not a dedicated half-star glyph: `Active=Half` variants are a `Masked Star` frame containing a `Masked Icon` group (a full `StarHalfFilled` icon instance) plus two sibling rectangle masks, `Half Full (always see this side)` and `Half Empty`, clipped to the star's own silhouette.
- **Real cross-page dependency, novel for this project:** the actual icon glyph masters composed inside `<Star>` (`StarSharp`, `StarHalfFilled`, `StarOutlineFilled`) live on the Icons page (`     Icons 🆗`, `6594:47638`), under `Master Container / Swatch`, not locally on the Rating page. Confirmed via a full 72-page scan (12,256 instances) that the only other instances of these three names anywhere in the file are 4 `StarSharp` instances on Icons' own page (its own self-catalog demo), not a foreign consumer. Rating's own raw MUI-import bindings (`components/rating/activeFill`, `components/rating/enabledBorder`) turned out to live entirely as per-instance overrides within `<Star>`'s own component set on Rating's page — **not on the shared Icons-page masters**, which were already correctly bound to the generic `Semantic/Icon/Default` token and were left untouched.
- Legacy content: the usual `_Library / Component Heading` + `Grid` wrapper (top-level frame simply named `Rating`, node `11017:144103`), with two separate `Container` sub-sections (one for `Star`, one for `<Rating>`), each with its own `_Library / Component Information` instance.
- Three pre-existing real-world mockups, but one shared pattern: `Rating: products` and `Rating: detached instances` (the second name is misleading — its content was confirmed live and correctly resolving, not detached) both compose the same reusable `_Custom / Sent Review` pattern, treated here as one real component consumed twice, not three independent mockups.

## 3. Completeness: real gaps, disclosed

- **`Active=False, Hovered=true` missing for all 3 sizes** (3 of 18 possible `<Star>` combinations): confirmed real via direct variant enumeration, not fabricated. Flagged in the Documentation frame's Sizing section footnote and in this doc.
- **No `readOnly` or `precision` variant axis on `<Rating>`**: MUI's `value`/`precision`/`readOnly`/`max` are all runtime props with no corresponding Figma variant property — flagged in the Key Props table rather than fabricated as variants that don't exist.
- **`icon`/`emptyIcon` custom-icon override props**: no matching instance-swap property exists yet on the real Figma masters, so a custom-icon example can't be shown from a real instance — flagged in Key Props, same class of gap as Checkbox's own `icon`/`checkedIcon`/`indeterminateIcon` disclosure.
- **Stock MUI's own default colors do not match Figma's approved values** — a genuine finding, not merely a disclosed gap: `#faaf00` (root) vs `#FFB400` (Figma), and `theme.palette.action.disabled` (this app's opaque `colors.grey[500]`) vs Figma's translucent `rgba(0,0,0,0.23)` outline. Unlike Radio's and FAB's own "zero override needed" precedent, `MuiRating` genuinely needed two explicit color overrides — see §6.
- 3 consecutive clean residual scans on both `<Star>` and `<Rating>` (manual recursive walk, not `findAllWithCriteria` — see §4) confirm zero remaining MUI-palette bindings, zero remaining unbound white, zero remaining unbound black across both masters.

## 4. What was found (discovery, before and during the build)

- Zero web-side presence existed before this pass: no `<Rating` usage anywhere in `src`, no `MuiRating` `brandTheme.ts` entry, no styleguide page, no `Rating.figma.tsx`. Same blank slate as Radio's own pass.
- **A `findAllWithCriteria`-based white-fill check returned a false negative (0 hits) on the first pass**, reproducing this project's own documented gotcha (`edge_ds_figma_findall_gotcha.md`) live rather than just citing it: a manual recursive walk of the same subtree found the real counts (19 on `<Star>`, 40 originally counted on `<Rating>`'s subtree), confirming the original Step 1 numbers were correct and the verification method, not the data, had been wrong.
- Of the 40 white-fill occurrences originally counted on `<Rating>`'s own subtree, only **6 were genuinely local** (one per variant's own root component) — the other 34 were inherited duplicates of `<Star>`'s own white fills (28 nested `Star #1`–`#5` instance overrides + 6 `Masked Star` frames) and cleared automatically the moment `<Star>`'s own masters were fixed, confirmed by direct before/after inspection of one representative nested instance's `boundVariables`.
- Checked `mainComponent.parent.id` resolution across both real-world mockups before and after every structural change (`Rating: products`: 22/22 instances resolved both times; `Rating: detached instances`: 40/40 both times) — zero broken links introduced by the reparent.
- Cross-component composition check (Chip, List — the two candidates most likely to embed a rating control): Chip, 0 of 267 instances. List, 1 `StarSharp` instance found but traced to `<ListItem>`'s own generic `<Icon>` instance-swap demo, unrelated to Rating — a false lead, not a real cross-component usage. Not a file-wide scan across all 73 pages, flagged as a scope limit rather than presented as exhaustive.

- **Legacy cleanup:** duplicated the legacy `Rating` wrapper as a safety net, reparented both real masters directly out of it (preserving node IDs), confirmed zero broken instance links via pre/post `mainComponent` resolution (137 Rating-family instances page-wide post-move, 0 unresolved), archived the emptied original to `🗄️ _Archive / Deprecated Docs` as `_Archive / Rating / 2026-08-11 / Rating (...)`, locked, then deleted the safety duplicate.

## 6. Web side

- **`MuiRating`:** new entry, and unlike Radio's or FAB's own "zero override needed" finding, this one genuinely needed color overrides — verified directly against `node_modules/@mui/material/Rating/Rating.js` (v7.3.9):
  - `root.color` set to `'#FFB400'` (`Components/Rating/Star/Active`) — stock MUI hardcodes a different literal, `'#faaf00'`, for this exact role.
  - `iconEmpty.color` set to `'rgba(0, 0, 0, 0.23)'` (`Components/Rating/Star/Border`) — stock MUI reads `theme.palette.action.disabled` here, which in this app's own theme resolves to the opaque `colors.grey[500]`, nothing like a translucent outline.
  - `size` needed **zero override** — stock MUI's own `small`/`medium`/`large` variants already render at 18px/24px/30px, pixel-identical to the real Figma masters' own geometry, confirmed directly rather than assumed.
- **Zero existing usage anywhere in `src`** (confirmed by grep) — nothing to regression-check on the web side.
- `npx tsc --noEmit` clean after the `brandTheme.ts` edit.
- No styleguide page built, per the ongoing Storybook-pause process change.
