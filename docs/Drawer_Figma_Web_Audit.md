## 3. Completeness: the missing anchor/variant axis

**This is the one confirmed, real gap in this pass, and it is explicitly out of scope to build.** The live master is a single `COMPONENT`, not a `COMPONENT_SET`. It cannot represent MUI's real `anchor` (left/right/top/bottom) or `variant` (temporary/persistent/permanent) props as Figma variant properties, because no such properties exist on it. The four real-world mockups on the page happen to only ever show a left-anchored drawer; the "no scrim" vs "with scrim" distinction that stands in for `variant` in this pass's Visual Preview illustration is a hand-composed approximation, not a real property.

Per explicit instruction, this pass did not build an `anchor` x `variant` variant set. **This is logged as a product gap for design to pick up as its own dedicated pass** (define the real variant axes, build the component-set, then re-run the token migration and Gallery/Documentation update against the richer master), the same way Backdrop's own `Style` x `Visibility` set was a separate, later pass after its initial audit first flagged the same kind of "real component, but structurally thin" gap.

## 7. 2026-08-07 chrome token rebind: Gallery/Documentation raw-hex cleanup

**Root cause.** A 2026-08-03 audit found and fixed raw/literal chrome colors (card backgrounds, borders, captions, body text) baked into the `Component Doc - EDGE-DS` master template itself, mapping them to existing `Semantic/*` and `Documentation/*` tokens. That fix does not retroactively reach any Documentation/Gallery frame that was cloned from an already-drifted ancestor rather than freshly instantiated after the fix. Drawer's frames were built 2026-08-05 from such a drifted lineage, so the same already-solved gap recurred here, not a new defect.

**What was rebound.** 64 raw fills/strokes across `Drawer - Component Gallery` and `Drawer - Documentation` chrome: white card/panel backgrounds → `Semantic/Surface/Paper`, 8%-alpha-black card borders → `Documentation/Border/Subtle` (deliberately forced to fully opaque solid grey, the same accepted 2026-08-03 precedent), black body/bullet text → `Semantic/Text/Primary`, grey caption/axis-label text → `Semantic/Text/Tertiary` and `Documentation/Text/Muted`. The real `<Drawer>` master COMPONENT was re-confirmed to still have empty `fills`/`strokes` arrays, untouched.

**Explicitly not touched, by design.** The rebind script never descends into any component instance except the Documentation template's own scaffolding slots, so it correctly left alone: the `_Library / Instance Slot` placeholder pattern; and the pre-existing, already-disclosed nested `List`/`ListItem`, `<Switch>`/`<BottomNavigationAction>`, and `<SwipeableDrawer>` sub-component debt inside the real-world mockups (87 instances skipped in total) — none of that is Drawer's own chrome, it belongs to those sub-components' own future migrations.

**Content investigation, not a defect.** A parallel discovery pass had flagged that the Anatomy & Token Architecture section's `Component Placeholder Slot` appeared to contain stale Checkbox-topic prose. Checked live `.characters` directly (not the node's `.name`, which Figma never re-syncs after a text edit): the real content is fully correct, Drawer-specific prose. No duplicate content exists; this was a stale-name false read, not a content bug.

**Verification.** 3 consecutive clean residual scans, 0 remaining matches for any of the raw values above. Visual spot-check confirmed no rendering regression (the new tokens resolve to the same or near-identical values as the raw colors they replaced).
