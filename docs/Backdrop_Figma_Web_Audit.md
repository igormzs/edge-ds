## 2. Design tokens & theme variables

| Token | Figma value | Web value | Verdict |
| :--- | :--- | :--- | :--- |
| Overlay color/opacity | `components/backdrop/fill` = `rgba(0, 0, 0, 0.5)` (identical in both `Light` and `Dark` modes, `MUI palette` collection) | MUI's stock default, hardcoded in `@mui/material/Backdrop` styles: `rgba(0, 0, 0, 0.5)` | **Visually matches, but coincidentally.** `brandTheme.ts` never reads `components/backdrop/fill` or defines an equivalent CSS variable - the web value is MUI's out-of-the-box default, not a value sourced from the Figma token. If either side changes independently (e.g. Figma's token gets restyled for a brand refresh), the two will silently drift with nothing to catch it. |
| Backdrop blur | **Now exists as a variant** (`Style=Blur`), but still no token: a literal `rgba(0,0,0,0.25)` fill plus a `BACKGROUND_BLUR` effect at radius `12` | Achievable ad hoc via `sx={{ backdropFilter: 'blur(6px)' }}` - no first-class prop, no design token backs a specific blur radius | **Gap narrowed, not closed.** Both sides can now represent Blur/Frost, but neither is backed by a shared token - the Figma radius (`12`) and Web's `6px` were chosen to look equivalent, not derived from one source of truth. | Transitions (duration/easing) | N/A - Figma is a static canvas; no motion tokens are modeled here, consistent with how every other component's docs treat this (a platform limitation, not a gap) | `transitionDuration = { enter: 225, exit: 195 }` (MUI default, `Fade` easing) | Not a discrepancy - expected asymmetry, not flagged as a gap. |

## 3. Variants & states

**Update, 2026-07-23:** a real `COMPONENT_SET` (`845:266424`) now exists with both requested axes as Figma variant properties. Table below reflects the resolved state.

| Requested axis | Figma | Web | Verdict |
| :--- | :--- | :--- | :--- |
| Visibility (`Visible` / `Hidden`) | Real `Visibility` variant property (`Visible` / `Hidden`) on every `Style` value. `Hidden` renders as an empty dashed placeholder rather than a fabricated fill, since there's genuinely nothing to paint | `open` boolean prop controls mount/unmount + fade transition | **Resolved.** Figma can now preview both states explicitly instead of the state being implicit/undocumented. |
| Style variants - Default (Dark Scrim) | `Style=Default, Visibility=Visible` (`6643:52207`, the original baseline), fill bound to `components/backdrop/fill` | `open` with no other props - default `rgba(0,0,0,0.5)` | Matches (see §2). |
| Style variants - Blur / Frost | `Style=Blur` variant, literal `rgba(0,0,0,0.25)` fill + `BACKGROUND_BLUR` effect (radius `12`) | `sx={{ backdropFilter: 'blur(6px)' }}` | **Resolved (structurally), gap narrowed (token).** Both sides can express it now; neither reads from a shared token. |
| Style variants - Transparent / Click-catcher | `Style=Transparent` variant - renders as an empty dashed placeholder in both `Visible` and `Hidden` states, since a true click-catcher paints nothing on either side (this sameness is accurate, not a modeling bug) | `invisible` boolean prop - renders a fully transparent backdrop that still captures pointer events (used for click-outside-to-close patterns without a visible scrim) | **Resolved (structurally).** Figma now has a dedicated variant matching the dedicated MUI prop, even though both are visually empty by design. |
| Style variants - Inverted / Light Scrim | `Style=Inverted` variant, literal `rgba(255,255,255,0.6)` fill, shown against a dark backing swatch in the docs canvas so the translucent white is actually visible (mirrors the Web demo's dark preview box) | `sx={{ backgroundColor: 'rgba(255,255,255,0.6)' }}` override | **Resolved (structurally), gap narrowed (token).** No dedicated token backs the value on either side (achieved via literal/`sx`, same caveat as Blur/Frost). |
| Interactivity - Dismissible vs. Persistent | Not representable (no boolean/variant property) | Consumer-controlled: passing `onClick` makes it dismissible; omitting it makes it persistent. Not a prop on `Backdrop` itself, but a usage pattern | **Still not a Figma gap** so much as a modeling choice - documented as a usage pattern on the page rather than expected as a Figma toggle. Not part of this pass's scope. |

## 4. Root cause (historical - resolved 2026-07-23)

The Figma "component" was never actually built out for EDGE-DS. It was the raw MUI Community library asset, left as-is inside an example composition (a mock dialog-over-backdrop scene, complete with the original MUI Figma-kit attribution footer) rather than promoted to a documented, variant-ized part of the system the way `Button`, `Alert`, `Accordion`, and the navigation components were. This has been addressed: a real `Style` x `Visibility` variant set (`845:266424`) now backs the component, built from the original baseline (`6643:52207`, preserved as the `Style=Default, Visibility=Visible` variant so nothing that referenced it broke).

## 5. Recommendation / what was built

**2026-07-23 update:** the variant set recommended below has been built. A real `COMPONENT_SET` (`845:266424`, in the new "Backdrop — Variant Set (Style × Visibility)" section on the `     Backdrop✅📃` page) now models `Style` (Default/Blur/Transparent/Inverted) x `Visibility` (Visible/Hidden) as 8 real variants. `Default`'s fill stays bound to `components/backdrop/fill`; `Blur` and `Inverted` use literal, non-tokenized fill values (flagged above, not fabricated as if they were tokens); `Transparent` and every `Hidden` variant render as an empty dashed placeholder rather than an invented fill. The documentation canvas's Visual Variants section (`815:262127`) now shows this full matrix in place of the single baseline swatch, and the Web Properties, Key Props, and Specs & Accessibility Notes sections were updated so they stop claiming "no Figma binding" for the three style variants that now have one.

**Master-template link note (unchanged):** the canvas was originally instantiated from `751:165195` (per `docs/DOCUMENTATION_STANDARDS.md`), then detached to a plain frame on 2026-07-21 so the Token Matrix and callout content could be nested directly inside the Specs & Accessibility Notes card - Figma's plugin API refuses `appendChild` into any frame nested inside a live instance, and the Specs card has no slot to receive new content (unlike Visual Variants/Orientation/Sizing/Interactive States, which do). Detaching only affected this one page; the shared master (`751:165195`) and every other component's documentation canvas built from it are untouched. The tradeoff: this page will no longer auto-inherit future structural changes to the master (e.g. a new note-slot addition) the way a live instance would - if the master gains a real "additional notes" slot down the line, this page would need that section rebuilt by hand.

**Still open, lower priority:** no dedicated Figma or Web token exists for the Blur radius or the Inverted scrim color - both remain literal values on both sides (see §2, §3). A future `components/backdrop/blur` and/or `components/backdrop/invertedFill` token pair is the natural next step whenever there's appetite for it, but no "official" value exists yet to standardize on, so none was fabricated in this pass.
