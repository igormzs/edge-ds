## 4. Root cause (historical - resolved 2026-07-23)

The Figma "component" was never actually built out for EDGE-DS. It was the raw MUI Community library asset, left as-is inside an example composition (a mock dialog-over-backdrop scene, complete with the original MUI Figma-kit attribution footer) rather than promoted to a documented, variant-ized part of the system the way `Button`, `Alert`, `Accordion`, and the navigation components were. This has been addressed: a real `Style` x `Visibility` variant set (`845:266424`) now backs the component, built from the original baseline (`6643:52207`, preserved as the `Style=Default, Visibility=Visible` variant so nothing that referenced it broke).

## 5. Recommendation / what was built

**2026-07-23:** the variant set recommended below was built. A real `COMPONENT_SET` (`845:266424`) models `Style` (Default/Blur/Transparent/Inverted) x `Visibility` (Visible/Hidden) as 8 real variants. `Transparent` and every `Hidden` variant render as an empty dashed placeholder rather than an invented fill.

**2026-07-31 update - token audit closed, Component Gallery built, Documentation frame upgraded to current structure:**
- Rebound `Style=Default`'s fill off the legacy `MUI palette` collection onto a new `Components/Backdrop/Fill/Default` (aliasing a new `Semantic/Overlay/Scrim`, promoted to Semantic tier since Modal/Dialog/Drawer all compose Backdrop and will want the same scrim). Created `Components/Backdrop/Fill/Blur` and `Components/Backdrop/Fill/Inverted` (both literal EDGE-palette values - no Brand-tier black/neutral primitive exists to alias to, and Figma variable aliases can't override alpha independently) and bound `Style=Blur`/`Style=Inverted` to them. Verified via `get_variable_defs` and two consecutive manual recursive residual walks (zero unbound `SOLID` fills remaining in the set).
- Built a proper `Backdrop - Component Gallery` frame (`1182:717`, cloned from Alert's ratified Gallery chrome) wrapping the real `845:266424` component set directly (reparented, not rebuilt from instances), with Style row labels and Visibility column labels read off the set's own real child positions. The previous bare `SECTION` wrapper (no Top Header, no Gallery Header) was removed once its content was confirmed safely relocated - all 8 pre-existing instances in the Documentation frame's Visual Variants section still resolve to the moved master.
- Trimmed the Documentation frame's Visual Variants preview to the `Visible` column only (4 illustrative states), per the "small representative preview, exhaustive matrix belongs to the Gallery" rule - the full 8-variant matrix now lives solely in the Gallery frame.
- Added the missing Category (`Components`) and Status (`Migrated ✓`) badges to the Title Row, alongside the existing MUI Docs badge (also rebound to the same token Alert's badge uses, for consistency).
- Replaced the old single "Specs & Accessibility Notes" catch-all with the current standard's split: a new "Anatomy & Token Architecture" section and a new "Usage Guidelines & Accessibility" section (both cloned from Alert's ratified structure, content rewritten for Backdrop), with the Key Props table moved to the final position.
- Relocated the legacy pre-master content (the original MUI Community mock dialog-over-backdrop scene) from an in-page section to the file's dedicated `🗄️ _Archive / Deprecated Docs` page, renamed `_Archive / Backdrop / 2026-07-31` and locked, per the "archive, don't delete" standard.
- This pass was scoped to the Figma side only. `brandTheme.ts` still has no `MuiBackdrop` entry reading the new tokens - syncing the web side is a follow-up pass, matching how other components' Figma and web passes were sequenced.

**Master-template link note (historical):** the canvas was originally instantiated from `751:165195`, then detached to a plain frame on 2026-07-21 so the Token Matrix and callout content could be nested directly inside the (now-removed) Specs & Accessibility Notes card.
