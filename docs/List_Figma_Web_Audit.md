## 3. Flagged structural product gaps (design-owned, not engineering leftovers)

- **`<ListSubheader>` is a single `COMPONENT`, not a `COMPONENT_SET`.** No `color`/`disableGutters`/`disableSticky`/`inset` variant axis exists. Needs a dedicated design pass to define the real axes before it can be built, same pattern as Backdrop's and Drawer's own initial "structurally thin" flags before their later passes. Not built this pass, per instruction.
- **`<ListItem>` carries MUI's pre-v5 interactive-state responsibility.** Its `State` axis (Hovered/Focus/Selected/Disabled) lives directly on `<ListItem>`, matching MUI's older API shape where `ListItem` itself was clickable. Current MUI (v5+) moves those states to a separate `ListItemButton` component and leaves `ListItem` non-interactive. Not restructured this pass, per instruction — flagged for a future dedicated pass if design wants to split them.
- **`<List>`'s `subheader` prop has no Figma slot equivalent.** Real-world usage (and MUI itself) composes a sibling `<ListSubheader>` instance instead — a reasonable, working pattern, just not literally the same as MUI's `subheader` prop.
